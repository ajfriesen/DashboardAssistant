# x86_64

Jeder Rechner, den der Mainline-Linux-Kernel ordentlich unterstützt, sollte
funktionieren. Die meisten Mini-PCs, alten Laptops und x86-Tablets eignen sich.
Das Image bringt breite Hardware- und Firmware-Unterstützung mit und ist nicht
auf ein einzelnes Board zugeschnitten. Dieselbe Datei bootet deshalb auf sehr
vielen verschiedenen Geräten.

## Anforderungen { #requirements }

- Boot per **UEFI** (das Image enthält eine EFI-Systempartition).
- Ein beschreibbarer Zieldatenträger: interne SSD/eMMC, ein SATA-Laufwerk oder
  ein NVMe-Laufwerk.
- Ein Touchscreen ist empfehlenswert, wenn du den Bildschirm fest montierst,
  aber nicht zwingend.

Das x86_64-Image ist das primäre, getestete Ziel. Wie sich die
Helligkeitsregelung an externen Monitoren verhält, steht unter
[Monitor dimmen](dimming.md).

## Kernel { #kernel }

Das Image läuft mit dem neuesten Mainline-Linux-Kernel. Aktuelle Mini-PCs,
Laptops und x86-Tablets bekommen Display, WLAN und Touch also, sobald die
Unterstützung upstream vorhanden ist. Zeigt ein Rechner nach dem Bootloader
einen schwarzen Bildschirm, hat kein WLAN, keinen Touch oder keine Steuerung
der Hintergrundbeleuchtung, dann
[eröffne bitte ein Issue](https://github.com/ajfriesen/DashboardAssistant/issues)
und sag uns, um welche Hardware es geht.

!!! note "Microsoft Surface"

    Das ist ein **Mainline**-Kernel, nicht das Patch-Set
    [linux-surface](https://github.com/linux-surface/linux-surface).
    Was upstream angekommen ist, funktioniert; was nicht, funktioniert nicht.
    Das betrifft vor allem die IPTS/IPU6-Kameras und einige Touch-Controller.

## Auf einen internen Datenträger installieren { #installing-onto-an-internal-disk }

Normalerweise baust du den Datenträger aus, schreibst das Image von einem
anderen Rechner darauf und baust ihn wieder ein. Wenn das nicht praktikabel
ist, etwa bei verlötetem eMMC oder einem Laptop, den du lieber nicht öffnen
möchtest, starte den Rechner von einem beliebigen Linux-Live-USB-Stick (Ubuntu,
Fedora, ein GParted-Live-Image, was du gerade hast) und schreib das Image von
dort auf den internen Datenträger. Denselben Weg beschreibt Home Assistant für
[Home Assistant OS auf generischem x86-64](https://www.home-assistant.io/installation/generic-x86-64/).

Lade das Image herunter, vergewissere dich, welches das Zielgerät ist, und
schreib es dann:

```bash
lsblk    # identify the internal disk — getting this wrong erases the wrong drive
# IMAGE_URL is the address of the x86_64 image — see Pick your image in Getting Started.
curl -L -o da.raw.xz "$IMAGE_URL"
xzcat da.raw.xz | sudo dd of=/dev/nvme0n1 bs=4M oflag=sync conv=fsync status=progress
```

Starte ohne den Live-USB-Stick neu. Das Gerät zeigt den Wartebildschirm, bis es eine Seed-Datei findet.
