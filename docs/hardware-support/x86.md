# x86_64

Any machine with decent mainline Linux support should work. Most mini-PCs, old
laptops and x86 tablets qualify. The image bundles broad hardware and firmware
support rather than being trimmed to one board, so the same file boots across a
wide range of devices.

## Requirements

- **UEFI** boot (the disk image ships an EFI system partition).
- A writable target disk: internal SSD/eMMC, a SATA drive, or an NVMe drive.
- A touchscreen is recommended if you are mounting the screen, but not required.

The x86_64 image is the primary, tested target. See
[Monitor dimming](dimming.md) for how brightness control behaves on external
monitors.

## Hardware too new for the supported image

The supported x86_64 image is built from a pinned, stable NixOS release, so its
kernel is a known quantity — and on very recent silicon a known quantity is
sometimes an old one. The symptoms are a black screen after the bootloader, no
Wi-Fi, no touch, or no backlight control.

For those machines there is a second, **best-effort** x86_64 image, built from
`nixos-unstable` with a mainline-latest kernel and the newer Mesa that comes with
it:

```bash
curl -L -o da.raw.zst \
  https://download.dashboardassistant.org/release/x86_64-unstable/latest.raw.zst
```

It is otherwise the same system — same partition layout, same
seed file, same in-place updates — and it stays on the unstable channel across
updates rather than drifting back to the stable one.

!!! warning "Best-effort means best-effort"

    This image is not tested on hardware before release. A newer kernel can
    regress things the supported one gets right. Flash the plain x86_64 image
    first and only reach for this one if that does not come up — and either way,
    please [open an issue](https://github.com/ajfriesen/DashboardAssistant/issues)
    telling us what you saw, because that is the only way this gets better.

!!! note "Microsoft Surface"

    This is a **mainline** kernel, not the
    [linux-surface](https://github.com/linux-surface/linux-surface) patch set.
    Whatever support has landed upstream works; what has not — notably the
    IPTS/IPU6 cameras and some touch controllers — does not. The promise is a
    newer kernel, not Surface support.

## Installing onto an internal disk

Normally you pull the disk, write the image to it from another machine, and put
it back. When that is not practical — a soldered eMMC, or a laptop you would
rather not open — boot the machine from any Linux live USB (Ubuntu, Fedora, a
GParted live image, whatever you have) and write the image onto the internal
disk from there. This is the same approach Home Assistant documents for
[Home Assistant OS on generic x86-64](https://www.home-assistant.io/installation/generic-x86-64/).

Download the image, confirm the target device, then write it:

```bash
lsblk    # identify the internal disk — getting this wrong erases the wrong drive
curl -L -o da.raw.zst https://download.dashboardassistant.org/release/x86_64/latest.raw.zst
zstdcat da.raw.zst | sudo dd of=/dev/nvme0n1 bs=4M oflag=sync conv=fsync status=progress
```

Reboot without the live USB. The device shows the waiting screen until it finds a seed file.
